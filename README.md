# Портфолио — каркас

Статический сайт: локально открыть `index.html` в браузере, сборка не нужна. Публикуется на GitHub Pages через сборку — см. «Публикация».

```
index.html          главная: Работы / По годам
project.html        лонгрид проекта: project.html?p=<slug>
info.html           «Обо мне»: фото, био, опыт, контакты
assets/css/style.css   токены, сетка, все стили
assets/js/data.js      ВСЕ данные: имя, интро, дисциплины, проекты
assets/js/common.js    шапка, тема, привязка к модулю, оверлей сетки
assets/js/index.js     календарь, визуальная сетка, фильтр
assets/js/project.js   сборка лонгрида из blocks
assets/js/preloader.js прелоадер: ASCII-галоп (кадры вшиты в файл)
assets/img/            картинки и видео
tools/gif-to-ascii.js  генератор ASCII-кадров для прелоадера из GIF
tools/build.js         сборка сайта для публикации → _site/
.github/workflows/     публикация на GitHub Pages
```

## Модульная сетка

| | Десктоп ≥1024 | Планшет 640–1023 | Мобильный <640 |
|---|---|---|---|
| Колонки | 12 | 8 | 4 |
| Гаттер / поля | 20 / 20 | 20 / 20 | 16 / 16 |
| Модуль `--u` | 20 | 20 | 20 |

- Ширины — целые колонки: `<div class="col" style="--d:6;--ds:4;--t:6;--m:4">` (ширина и старт для десктопа, планшета, мобильного). Вложенная ячейка эти значения не наследует.
- Две колонки на всём сайте: **служебная** 1–4 (имя, год и месяц, метки, ключи) и **контент** 5–12 (интро, названия, текст, картинки). На планшете 1–2 и 3–8, на мобильном одна колонка.
- Отступы и высоты кратны 20px. Линии рисуются inset-тенью, поэтому ритм не сдвигается.
- Высота картинки округляется до модуля (кроп ≤ 10px). Если под картинкой подпись, то картинка с отступом до подписи занимают целое число модулей. Отключить для одной картинки: `snap: false`.
- **G** — показать или скрыть оверлей колонок и модульных линий.

Шрифт: IBM Plex Mono 400, размеры `--fs-1` 14/20 (весь текст) и `--fs-2` 28/40 (заголовок проекта).

## Шапка и главная

**Шапка** на всех страницах — одна строка: «Михаил Никулин» | «РАБОТЫ  ПО ГОДАМ  ОБО МНЕ» | «− +  ◐». Навигация (и внизу кейса «← ВСЕ РАБОТЫ», «СЛЕДУЮЩИЙ:») — капсом через CSS, тексты в данных обычные. Имя ведёт на главную, контакты — на «Обо мне». На главной «Работы / По годам» переключают вид, «− +» (зум) видны только в «Работах»; с других страниц они ведут на главную в нужном виде. Главная открывается «Работами» (сетка), «По годам» (календарь) — `?view=calendar`. Линия под шапкой прибита к ней и при прокрутке остаётся на месте.

**Первый экран главной** пустой: работы начинаются с середины экрана, округлённой вниз до модуля 20px (`.home` в `style.css`). Фото (`SITE.photo`, файл `assets/img/me.jpg`; при наведении, а на телефоне по тапу — `me-smile.jpg` из `photo.hover`) и био (`SITE.bio`) — на странице «Обо мне».

**По годам** (календарь): год → месяцы → проекты. Колонки: проект | тип | клиент | срок. Проект стоит в месяце запуска (`end`), идущий (`end: null`) — в текущем месяце. В колонке типа — основной тип (первый в `d`), полный список — в карточке сетки и в мете кейса. При наведении линия отмечает все месяцы проекта, у курсора появляется обложка. Число после названия — соавторы, имена в подсказке.

**Работы** (главная, сетка): masonry на колонках, под картинкой название, год, клиент и тип. Кнопки − / + (или клавиши − / +) меняют число карточек в ряду: 12/6/4/3/2 на десктопе, 8/4/2/1 на планшете, 4/2/1 на мобильном. На самых мелких уровнях подписи скрыты. `wide: true` — карточка двойной ширины.

Тип проекта везде пишется словом: «веб», «мобайл», «графика» (`DISCIPLINES` в `data.js`). Цветовой кодировки и фильтра нет: на 10–15 проектах хватает двух видов. Если работ станет больше, фильтр можно вернуть отдельной строкой в панели видов.

## Добавить проект

В `assets/js/data.js` → `PROJECTS` (поля описаны там же). Минимум:

```js
{ slug: "new-case", title: "Название", client: "Клиент", d: ["web"],
  start: "2026-05", end: "2026-09",
  cover: { src: "assets/img/new-case/cover.jpg", ratio: "4 / 5" },
  blocks: [ ... ] }
```

`show: ["calendar"]` или `show: ["grid"]` — показать только в одном виде. `href` вместо лонгрида — внешняя ссылка.

## Блоки лонгрида — осевая композиция

Ось — промежуток между колонками 4 и 5 (на планшете — 2 и 3). Слева от оси всё прижато к ней и выровнено вправо: метки разделов, ключи меты, подписи, маленькие картинки. Справа всё начинается от неё: заголовок, текст (колонки 5–9), картинки. На мобильном оси нет — одна колонка, всё влево.

```js
{ type: "text", label: "03 Решение", text: "Абзац.\n\nНовый абзац.", aside: { src, ratio, caption } }
{ type: "media", items: [{ src, ratio, caption, size, side }] }
```

Ширина картинки — из шкалы 2 / 3 / 5 / 8 колонок, `12` — на всю ширину. `side: "left"` — слева от оси (не больше 4 колонок). Если `size` и `side` не заданы, раскладка подбирается сама:

| В ряду | Раскладка |
|---|---|
| 1 горизонтальная | первая картинка кейса — на всю ширину, остальные — 8 колонок |
| 1 вертикальная / квадратная | 3 / 5 колонок от оси |
| 2 | первая мелко слева от оси (3), вторая крупно справа (8, вертикальная — 5) |
| 3 и больше | первая слева от оси (3); остальные справа: вертикальные по 2, горизонтальные 5 + 3; лишние переносятся на следующий ряд от оси |

- Порядок важен: первая картинка в ряду — ключевая, она встаёт слева от оси.
- Подписи: у одиночной картинки — на поле у оси, вровень с её нижним краем; в рядах — под каждой картинкой.
- `aside` у текстового блока — деталь на поле под меткой раздела: 2 колонки, `size: 3` — шире.
- Планшет: ширины ужимаются (8 → 6, 5 → 4), картинки слева от оси — на поле 1–2. Мобильный: всё подряд, вертикальные — по две в ряд.

Гифки интерфейса лучше сохранять в `.mp4` или `.webm`: они легче в 5–10 раз. Видео играет без звука по кругу, а при включённом в системе «уменьшении движения» показывается с кнопками управления. Без `src` на месте медиа выводится серый плейсхолдер с пропорцией.

## Прелоадер

ASCII-галоп по кадрам Эдварда Майбриджа («Animal Locomotion», 1887, общественное достояние). 15 кадров по 100×35 знаков вшиты в `assets/js/preloader.js`, поэтому прелоадер появляется сразу: грузить ему нечего.

- Стоит в колонке текста (5–9), по вертикали в центре; размер знака подгоняется под ширину колонки, не больше 10px.
- Показывается при первом заходе за сессию, пока грузится страница: не меньше одного шага галопа (~1 с), не дольше 6 с. При переходах между страницами не повторяется.
- С включённым в системе «уменьшением движения» — один неподвижный кадр.
- Темп — `FRAME_MS` в `preloader.js` (сейчас 70 мс на кадр).
- Другая анимация или плотность: `node tools/gif-to-ascii.js анимация.gif [ширина]` (нужен Playwright, команда установки — в начале файла). Генератор заменяет только кадры между метками `FRAMES:START` и `FRAMES:END`.
- Отключить — убрать `<script src="assets/js/preloader.js">` из `index.html`, `project.html`, `info.html`.

## Публикация (GitHub Pages)

При каждой отправке в ветку `main` GitHub Actions запускает `node tools/build.js` и выкладывает папку `_site`. В git `_site` не хранится.

Что делает сборка:
- для каждого кейса — страница `work/<slug>/` с заголовком, описанием и превью для мессенджеров (Open Graph), текст кейса — в `noscript` для поисковиков;
- те же мета-теги — у главной и «Обо мне»;
- `sitemap.xml`, `robots.txt`, `404.html`.

На опубликованном сайте ссылки ведут на `work/<slug>/`, локально — как раньше, на `project.html?p=<slug>`.
Картинка превью ссылки: обложка кейса → первая картинка кейса → фото из «Обо мне».
Адрес сайта на GitHub Pages подставляется при сборке сам. `SITE.url` в `data.js` нужен, только если подключишь свой домен.

Один раз:
1. Создать на GitHub публичный репозиторий и отправить в него код (бесплатные Pages работают с публичными репозиториями).
2. Settings → Pages → Source: **GitHub Actions**.

Посмотреть сборку локально: `node tools/build.js && python3 -m http.server -d _site 8000` → http://localhost:8000.
